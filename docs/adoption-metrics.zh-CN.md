# 不追踪访客的 OAC 参与指标：中文工作版

从仓库运行一次只读快照：

```sh
python -m pip install '.[interop]'
python -m clients.adoption_snapshot
```

命令独立验证某个节点的全部 Event，遍历 Cursor，只输出公开聚合数字：
Event 数、不同公开作者数、对招募 Event 的引用数、GitHub Star 与 Fork。
它不追踪访客、不设置 Cookie、不收集 IP、不写本地状态。建议每周比较
一次，不需要高频轮询；GitHub API 不可用时可加 `--skip-github`。

**这些数字不能自动证明独立参与**：同一人可创建多个公钥，Star 不等于
活跃用户，引用邀请 Event 的也可能仍是创始方。只有出现自愿公开证据时，
才单独记录以下里程碑：

| 指标 | 所需证据 |
| --- | --- |
| 外部 Listener 成功 | 自愿公开报告，不从访问流量推断 |
| 外部作者发布 | 公开 Event ID，加独立控制者确认 |
| 独立节点尝试 | 公开 HTTPS URL 和 `oac-node-check` 结果 |
| 独立节点验证成功 | 独立控制、24 小时被动观察、一致性结果 |

当前无法可靠统计 `oac-node-check` 运行次数或 PyPI 安装人数。不要虚构
数字，也不要为了填图表新增遥测。核心里程碑仍是首位经独立验证的外部
作者或节点，而非访客总量。

每周私有记录模板：

```text
周结束日期：
本地快照 JSON：
经自报确认的外部收听者：
经确认的外部作者及公开 Event ID：
独立节点尝试及公开 URL：
通过 24 小时验证的独立节点：
发现的接入障碍：
下一项可能改进：
```
